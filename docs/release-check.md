## 分发与运行时核验

以下步骤需针对实际分发包和安装目标执行，源码测试不能替代安装结果：

1. `pnpm pack` 后检查实际 tgz 文件清单：Host、Client、patch、默认模板、locale、原始图标、许可与文档；不包含私有数据、`.git`、`.local` 或开发测试目录。
2. 解包后运行 `tests/packed-smoke.mjs <package-dir>`：从实际包加载模块、创建基础人格，检查规范槽位工具写入与组合；确认不自动应用，删除基础人格后重新加载不复活。
3. 通过 DSH 插件管理安装该 tgz，以 `application` 和 warnings 为准；读取 Host 工具 schema 和状态，不以未变化的 Client slot ID 证明浏览器已经加载新代码。
4. 升级前后核对完整人格目录文件清单与 SHA-256，包含人设、设置、应用快照与初始化记录；不以真实用户数据执行修改性测试。
5. 核验安装包的显示元数据、locale 与图标资源，确认实际安装的 Host/Client 与候选一致；署名保持 `xiaoxing-nya <xiaoxing_bot@luoli.my>`，只使用仓库级 Git 设置。

前一候选 `0.2.0-rc.1` 已在 DSH `0.2.2-rc.1` 的 desktop profile 从 tgz 安装，返回 `application: applied`、无警告，状态可用；当时已有的人格、设置与应用快照三个文件升级前后 SHA-256 一致。这是上一候选的实机记录，不预先证明本候选在任意目标 profile 的安装状态。

## 验证边界与人工复核

- 隔离测试、静态入口检查和 Client 注册检查不是视觉或点击测试；没有创建模拟页面代替真实 GUI 验证。
- 刷新现有 DSH 页面后，人工检查只有一个预览按钮、展开/收起、空组合、错误提示与 personality 下拉项；核对明暗主题。
- 涉及应用或 AI 编辑时，还需复核覆盖确认、部署人格确认、错误提示与 AI 会话跳转。
- 真实宿主接口核验基于 `0.2.2-rc.1`，未对兼容区间内每个版本进行实机验证；升级宿主后应复测。
- home patch / 命令行覆盖控制的配置可能拒绝 profile 写入，此时返回 `config-authority`，应修改原始配置层，不尝试绕过。
- YAML 导入是所需子集，不是通用完整 YAML 解析器；外部人设仍需用户审阅。
- 无持久化监听器的 profile 可使用临时 AI 会话，`flush(false)` 不是数据落盘保证；重启恢复取决于宿主是否提供持久化。
